## Verification performed locally

- Python: `.venv/bin/python -m pytest -q` — 64 tests passed; `.venv/bin/python -m ruff check .`, `ruff format --check .`, `manage.py check`, and `manage.py makemigrations --check --dry-run` passed. Onboarding tests cover both candidate feeds, policy gating, URL boundaries, validation without storage, and safe XML mapping with atomic output.
- API packaging: `docker build -f Dockerfile.api -t fashion-finder-api:xml-mapping-check .` passed. `docker run --rm --entrypoint fashion-finder fashion-finder-api:xml-mapping-check map-xml-feed --help` showed the packaged command. This is a local packaging check, not a live partner-feed test.
- Web: `npm run typecheck`, `npm run lint`, and `npm run test` passed with local Node 22.23.3. The optimized `npm run build` passed with Node 24.15.0 after allowing Next.js to start its TypeScript subprocess. The Docker image has not been rebuilt for this change.
- Local Docker smoke, using an isolated temporary data directory and **synthetic** approved policy: the migration completed, API became healthy, and the worker imported one timestamped Reserved fixture. The API and the web proxy returned the same search result; Django admin CSS returned HTTP 200. Chromium searched the catalogue at 390 px without horizontal overflow and displayed an in-memory photo preview with the unavailable-matching message. A malformed uploaded image returned 422; a valid PNG returned the expected 503. `analytics-report` showed one aggregate text-search counter, and a second worker run reported the feed unchanged. After rebuilding the final API image, the recreated stack again returned HTTP 200 for health and search. A SQLite backup copied to a separate file passed `integrity_check` and contained the synthetic offer.
- Django HTTP smoke on a local loopback server with a temporary SQLite file and **local-only synthetic policy**: `GET /api/v1/health` returned `ok` and `image_search: unavailable`; `GET /api/v1/search?max_price=15000` returned one synthetic 9,995 Ft jacket; `GET /admin/login/` returned HTTP 200. A copied pre-Django `data/fashion_finder.sqlite` migrated successfully and the original file's hash remained unchanged. No retailer source or deep link was live-tested by this fixture.
- SQLite `EXPLAIN QUERY PLAN` on a category search used the source/market unique index and the new `offer_public_filter_idx` for retailer, status, currency, and category. This is a query-plan check, not a live traffic latency measurement.
- Local CLI smoke on a temporary SQLite catalogue and synthetic approved policy: `readiness --category jackets` counted one eligible Reserved offer and correctly failed the two-source threshold; `audit-sample` wrote one eligible review row. No retailer permission or live product page was checked.
- Local CLI smoke on a temporary SQLite catalogue and synthetic completed review: `audit-report` counted one passing row and correctly failed the two-source audit threshold. This did not verify a live retailer page or a real reviewer.
- Dependency review: `npm audit --omit=dev` found zero production dependency vulnerabilities. Full `npm audit` reported five high advisories in the development-only `eslint-config-next` → `fast-glob` → `micromatch` → `braces` chain; npm offered only a breaking downgrade to Next 14 tooling. Recheck when upstream publishes a compatible fix.

**Release state:** local Docker flow is runnable; private beta is not ready. The two-source rights gate, 30-offer audits per source, 30 real shopping tasks, permitted image relevance evaluation, and live approved-source smoke test remain open. Do not substitute the synthetic local smoke test for any of them.
