# Application implementation status

## Update, 25 October 2026

- **Search:** photo search focuses on the garment automatically, reads category and
  colour, offers other garments in the photo and folds colour variants. Look search
  reads Hungarian (476-entry fashion dictionary with suffix and compound handling,
  price and size phrases) and blends photo and product-text similarity. Measured on
  the practice catalogue: Hungarian phrase MRR@10 0.876 → 0.958; photo → category
  Hit@5 0.937 → 0.953; garment inside a street photo Hit@1 0.35 → 0.60 (see
  [benchmark results](benchmark-results.md)).
- **Scraper:** discovery and refresh are separate; a due-queue scheduler (migration
  0004) backs off on failures and needs two 404s six hours apart to remove an offer;
  robots, Crawl-delay and opt-outs are honoured; a token-protected ingest API and a
  scheduled GitHub Actions refresh exist (the workflow skips until its secrets and a
  persistent API are set). See the [scraper guide](scraper.md).
- **Practice catalogue:** about 3,600 licence-safe public-dataset products, loaded only
  into their own data directory ([guide](practice-catalogue.md)).
- **Local real-data run:** 5,000 current offers from Reserved, Sinsay, Mohito, House and
  Cropp (1,000 each, none rejected); 1,500 photos fetched and indexed with the INT8
  FashionSigLIP model; word, look and photo search verified in the API and the browser.
  The shops were approved for local evaluation only; the repository's policies stay
  pending.
- **Checks:** 294 Python tests, ruff, web typecheck, lint, tests and build pass.

The release state below is unchanged: no source is approved for public use, and the
30-task shopper evaluation has not been run.

## Verification performed locally

- Python: `.venv/bin/python -m pytest -q` — 75 tests passed; `.venv/bin/python -m ruff check .`, `ruff format --check .`, and Django system check passed. Onboarding tests cover both candidate feeds, policy gating, URL boundaries, validation without storage, and safe XML mapping with atomic output. Image-index tests cover permission gating, ranking, filters, stale URL exclusion, atomic rejection of invalid manifests, model checksums, and encoder-version mismatch. Ranking-replay tests cover actual text/photo result IDs, shared filters, source revocation, private output, invalid local photo paths, safe validation errors, and demo exclusion.
- Ranking-replay CLI smoke: an isolated temporary SQLite catalogue contained three synthetic current jackets from two declared sources and one bundled CC0 image. `index-images` then `evaluate-rankings` returned three relevant text top-five and photo top-five results. The single synthetic task correctly did not pass the 30-task gate. This is not shopper relevance evidence or retailer permission evidence.
- API image packaging: `docker build -f Dockerfile.api -t fashion-finder-api:ranking-evaluation .` passed; `docker run --rm --entrypoint fashion-finder fashion-finder-api:ranking-evaluation evaluate-rankings --help` showed the packaged command.
- API packaging: `docker build -f Dockerfile.api -t fashion-finder-api:xml-mapping-check .` passed. `docker run --rm --entrypoint fashion-finder fashion-finder-api:xml-mapping-check map-xml-feed --help` showed the packaged command. This is a local packaging check, not a live partner-feed test.
- Web: `npm run test`, `npm run typecheck`, `npm run lint`, and optimized `npm run build` passed with Node 24.15.0. The Docker web image was rebuilt for the synthetic demo smoke test.
